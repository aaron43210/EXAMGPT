=== page 1 ===
Process Concept
A process is a program in execution. A process has a text section (program code), a data section (global variables), a heap for dynamically allocated memory and a stack for function parameters, return addresses and local variables.
The Process Control Block (PCB) stores everything the operating system needs to know about a process: the process state, program counter, CPU registers, CPU-scheduling information, memory-management information, accounting information and I/O status information.
Process states: new, ready, running, waiting (blocked) and terminated. A process moves from running to waiting when it requests I/O and from waiting to ready when the I/O completes.
A context switch saves the state of the running process into its PCB and loads the saved state of the next process. Context-switch time is pure overhead because the system does no useful work while switching.

=== page 2 ===
Threads
A thread is the basic unit of CPU utilisation; it has its own thread ID, program counter, register set and stack, but shares the code section, data section and open files with the other threads of the same process.
Benefits of multithreading are responsiveness, resource sharing, economy (creating a thread is cheaper than creating a process) and scalability on multicore processors.
User-level threads are managed by a thread library without kernel support; kernel-level threads are managed directly by the operating system. In the many-to-one model, one blocking system call blocks the entire process.

=== page 3 ===
CPU Scheduling
First-Come, First-Served (FCFS) scheduling runs processes in the order they arrive. It is non-preemptive and suffers from the convoy effect, where short processes wait behind one long process.
Shortest-Job-First (SJF) scheduling picks the process with the smallest next CPU burst. SJF is provably optimal: it gives the minimum average waiting time for a given set of processes. Its preemptive version is called Shortest-Remaining-Time-First (SRTF).
Round Robin (RR) gives each process a fixed time quantum, typically 10 to 100 milliseconds. If the quantum is very large RR behaves like FCFS; if it is very small the context-switch overhead dominates.
Priority scheduling can cause starvation of low-priority processes. Aging solves starvation by gradually increasing the priority of processes that wait for a long time.
Scheduling criteria include CPU utilisation, throughput, turnaround time, waiting time and response time.

=== page 4 ===
Process Synchronization
A race condition occurs when several processes access and manipulate shared data concurrently and the outcome depends on the particular order in which the accesses take place.
A solution to the critical-section problem must satisfy three requirements: mutual exclusion, progress and bounded waiting.
Peterson's solution is a classic software solution for two processes that uses a shared turn variable and a flag array.
A semaphore is an integer variable accessed only through two atomic operations, wait() (P) and signal() (V). A binary semaphore behaves like a mutex lock; a counting semaphore controls access to a resource with a finite number of instances.
Classic synchronization problems are the bounded-buffer (producer-consumer) problem, the readers-writers problem and the dining-philosophers problem.

=== page 5 ===
Deadlocks
A deadlock is a situation in which every process in a set is waiting for an event that can be caused only by another process in the set.
Deadlock can arise only if four conditions hold simultaneously (the Coffman conditions): mutual exclusion, hold and wait, no preemption and circular wait.
A resource-allocation graph with no cycles has no deadlock. If each resource type has exactly one instance, a cycle in the graph implies a deadlock.
Deadlock prevention ensures that at least one of the four necessary conditions cannot hold, for example by requiring processes to request all resources at once to break hold and wait.

=== page 6 ===
Deadlock Avoidance and Recovery
Deadlock avoidance requires advance information about the maximum resources each process may request. A state is safe if the system can allocate resources to every process in some order (a safe sequence) and still avoid deadlock.
The Banker's algorithm is a deadlock-avoidance algorithm for multiple instances of each resource type. It uses the Available, Max, Allocation and Need matrices, where Need = Max - Allocation, and grants a request only if the resulting state is safe.
Deadlock detection periodically runs an algorithm that checks for a cycle in the wait-for graph. Recovery options are process termination (abort all deadlocked processes or one at a time) and resource preemption with rollback.

=== page 7 ===
Memory Management and Paging
Logical addresses are generated by the CPU; the Memory Management Unit (MMU) maps them to physical addresses at run time.
External fragmentation is free memory split into small non-contiguous holes; internal fragmentation is unused space inside an allocated block.
Paging divides physical memory into fixed-size blocks called frames and logical memory into blocks of the same size called pages. Paging eliminates external fragmentation but can still cause internal fragmentation in the last page.
The page table maps each page number to a frame number. A Translation Look-aside Buffer (TLB) is a small, fast associative cache of page-table entries; the effective access time depends on the TLB hit ratio.
Segmentation divides a program into variable-sized logical units such as code, stack and heap, which matches the programmer's view of memory.

=== page 8 ===
Virtual Memory
Virtual memory separates logical memory from physical memory, allowing a program to execute even when it is only partly in memory.
Demand paging loads a page only when it is referenced. A reference to a page that is not in memory causes a page fault, and the operating system brings the page in from the backing store.
Page replacement algorithms: FIFO replaces the oldest page and suffers from Belady's anomaly, where adding frames can increase the number of page faults. The Optimal algorithm replaces the page that will not be used for the longest time and has the lowest page-fault rate, but it requires future knowledge. LRU replaces the page that has not been used for the longest time.
Thrashing happens when a process spends more time paging than executing because it does not have enough frames for its working set. The working-set model and page-fault-frequency control are used to prevent thrashing.

=== page 9 ===
File Systems
A file is a named collection of related information recorded on secondary storage. Common allocation methods are contiguous allocation, linked allocation and indexed allocation.
Linked allocation has no external fragmentation, but supports only sequential access efficiently. The File Allocation Table (FAT) is a variant of linked allocation that keeps the links in a table at the start of the volume.
Indexed allocation brings all pointers together into an index block, which supports direct access. Unix inodes combine direct blocks with single, double and triple indirect blocks.

=== page 10 ===
Disk Scheduling
Disk scheduling reduces seek time, the time for the disk arm to move to the cylinder containing the requested sector.
FCFS disk scheduling is fair but does not minimise head movement. SSTF (Shortest Seek Time First) selects the request closest to the current head position and may cause starvation.
SCAN, also called the elevator algorithm, moves the head from one end of the disk to the other, servicing requests on the way, then reverses. C-SCAN returns to the beginning without servicing requests on the return trip, giving a more uniform waiting time. LOOK and C-LOOK only go as far as the last request in each direction.
